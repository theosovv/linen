# 0006. Детерминированное состояние sine

- Статус: принят.
- Дата: 2026-11-16.

## Контекст

Beep содержит первый stateful-узел. Его начальное состояние, порядок вычисления семпла и обновления фазы, отрицательные частоты и reset должны быть одинаковыми в наивном интерпретаторе, reference и последующей VM. Обновление фазы один раз за блок изменило бы наблюдаемую семантику.

## Варианты

1. Вычислять `sin(2π × freq × n / sample_rate)` без сохранённой фазы. Это просто для константной частоты, но не обобщается на сигнальную частоту и накапливает другую числовую погрешность.
2. Хранить phase в периодах как `f64`, выдавать текущее значение и затем обновлять phase на каждом семпле. Это прямо соответствует спецификации и поддерживает `freq: Sig`.
3. Хранить угол в радианах как `f32`. Представление компактнее, но быстрее теряет точность и меняет заданный контракт.

## Решение

Выбран второй вариант.

Для каждого вызова `sine` создаётся независимое состояние:

```text
initial phase = 0.0                  # f64, периоды

sample:
    if freq is not finite:
        runtime E4001 before changing phase
    value = sin(2π × phase) as f32
    phase = (phase + freq / sample_rate).rem_euclid(1.0)
    return value
```

- `freq` из runtime `f32` перед формулой переводится в `f64`; sample rate — валидированный ненулевой `u32`.
- Отрицательная частота использует Euclidean modulo, поэтому phase всегда остаётся в `[0, 1)`.
- Нулевая частота даёт постоянный нулевой сигнал при исходном состоянии.
- Конечная частота выше Nyquist не отклоняется и естественно даёт aliasing.
- Нечисловая частота возвращает `E4001` с primary span frequency expression и фактическим `sample_index`; phase до ошибки не изменяется. Renderer также проверяет итоговый `out` на каждом семпле.
- `reset()` возвращает phase каждого экземпляра к `0.0`. Повторный рендер после reset начинается с того же первого семпла.
- На этапе 2 исполнение посемпловое. Будущий block VM обязан сохранить тот же порядок на каждом семпле независимо от partition.

## Последствия

- Два вызова `sine` не разделяют состояние, даже если их аргументы совпадают.
- `SourceId`, `BindingId`, `BuiltinId`, физический путь и порядок hash iteration не участвуют в фазе или звуке.
- Точные биты `sin` на всех платформах не обещаются; сравнения используют согласованный допуск из ADR 0009.
- Reference не вызывает production `Sine`, чтобы общий дефект state transition не скрылся в differential test.

## Проверка

- При 48 000 Гц и `sine(480)` проверяются индексы `0`, `25`, `50`, `75`, `100` и значения `0`, `1`, `0`, `-1`, `0` с допуском `2e-5 + 2e-5 × abs(expected)`.
- Отдельно проверяются усиление, нулевая/отрицательная/высокая частота, длинный рендер с конечной phase и reset.
- Nonfinite frequency и nonfinite output проверяют код, primary `SourceSpan`, `sample_index` и отсутствие итогового частичного WAV.
- Reference и production сравниваются посемплово, но аналитические vectors остаются основным oracle корректности формулы.
